Laravel 13 изнутри: жизненный цикл запроса, Service Container, Eloquent и pivot-связи, коллекции, middleware, авторизация, события и очереди на RabbitMQ, почта и уведомления, кэш на Redis, realtime через Reverb, тесты — на таск-трекере с ролями. Минимальный фронт на чистом Vue. 10 сессий.

Как устроена лаба. Разделы 1–11 — теория «под капотом» по каждому слою фреймворка: не «как вызвать», а «что при этом происходит». Раздел 12 — десять сессий заданий по возрастанию: стенд и схема данных → Eloquent-связи → коллекции и API Resources → HTTP-слой → контейнер и провайдеры → авторизация + Vue-фронт → события и очереди на RabbitMQ → почта, уведомления, планировщик → кэш и realtime → тесты и финал. Каждый шаг: код → «зачем» → команда → ожидаемый результат → «проверь себя». Разделы 13–16 — чек-лист, глоссарий, вопросы для собеседования, что дальше.

Стек: Laravel 13 / PHP 8.4, PostgreSQL 17, Redis 7, RabbitMQ 4, Mailpit, Laravel Reverb; фронт — Vue 3 + Vite (JavaScript, только API-клиент). Всё в Docker. Базовые вещи (роутинг, контроллеры, миграции, Blade) даны ссылками на документацию и используются без разбора. Ссылки на ООП-лабу — там, где нужны принципы; ссылки на RabbitMQ-лабу — там, где очереди.

Laravel «магический» ровно до тех пор, пока не открыт исходник vendor/laravel/framework. 🔬 Под капотом: Octane и long-running: почему «состояние в статике» — баг

В классическом режиме (php-fpm, artisan serve) приложение создаётся на каждый запрос, и любое состояние умирает вместе с ним. Под Octane/Swoole/FrankenPHP Application живёт между запросами: singleton'ы, статические свойства, $this->cache в провайдере — переживают запросы и текут между пользователями. Правило, которое стоит соблюдать заранее: singleton — только для безсостояния (клиенты, менеджеры); всё, что зависит от запроса, — scoped (сессия 5).

Фасад — статический прокси: Cache::get() → Facade::__callStatic → app('cache')->get(). Ключ берётся из getFacadeAccessor(). Отсюда: (1) фасад тестируется через подмену биндинга (Cache::fake() = instance('cache', new Fake)); (2) фасад — не «глобальная функция», а сахар над DI, и в конструктор можно попросить тот же объект через контракт. Real-time facades (use Facades\App\Services\Foo) делают то же для любого класса.

Провайдер — единственное место, где приложение говорит контейнеру, что чем является. register() — биндинги, boot() — всё остальное. DeferrableProvider — регистрируется только при первом запросе своего сервиса (для тяжёлых пакетов).

when(X)->needs(Y)->give(Z) и tag/tagged — контейнер сам подставляет нужную реализацию по контексту, ровно тот же Strategy, что и в ООП-лабе, только выбор делает не ваш код, а DI. extend — тот же Decorator из ООП-лабы: оборачивает объект уже после того, как его собрал контейнер.

🔬 Под капотом: pivot: почему $user->workspaces[0]->pivot->role работает, и когда не работает

belongsToMany при загрузке делает select users.*, workspace_user.workspace_id as pivot_workspace_id, workspace_user.user_id as pivot_user_id — только ключи. Чтобы получить role, нужно ->withPivot('role'), иначе $pivot->role будет null без ошибки — источник половины «не работает». ->withTimestamps() — если в pivot есть created_at. ->using(Membership::class) — свой класс Pivot с кастами (enum роли), методами, событиями. ->as('membership') — переименовать $user->pivot в $user->membership. attach($id, ['role' => 'admin']) — вставка с данными; sync([1 => ['role' => 'x'], 2]) — привести к точному набору; syncWithoutDetaching — только добавить; updateExistingPivot — изменить данные. Всё это — сессия 2, с SQL-логом на каждый вызов.

Casts и атрибуты. $casts (или casts()) превращает колонку в тип при чтении и обратно при записи: 'status' => TaskStatus::class (enum), 'meta' => 'array', 'due_at' => 'datetime', AsCollection, свои CastsAttributes. Attribute::make(get:, set:) — accessor/mutator одним методом. Scopes: локальные (scopeOpen → ->open()) и глобальные (addGlobalScope — SoftDeletes так работает). N+1: Model::preventLazyLoading(!app()->isProduction()) в провайдере превращает каждую случайную ленивую загрузку в исключение — включите с первого дня.

6. HTTP-слой: middleware, Form Requests, Resources, исключения #

// Middleware = обёртка вокруг $next — тот же Decorator, что в ООП-лабе
public function handle(Request $request, Closure $next, string $role = 'member'): Response
{
    // «до»: проверка / изменение запроса
    if (! $request->user()?->isMemberOf($request->route('workspace'), $role)) abort(403);
    $response = $next($request);                 // весь остаток пайплайна: другие middleware, контроллер
    // «после»: изменить ответ
    return $response->header('X-Workspace', $request->route('workspace')->id);
}

enum Role: string
{
    case Owner = 'owner'; case Admin = 'admin'; case Member = 'member'; case Viewer = 'viewer';

    public function atLeast(self $min): bool                        // owner > admin > member > viewer
    {
        $order = [self::Viewer, self::Member, self::Admin, self::Owner];
        return array_search($this, $order, true) >= array_search($min, $order, true);

}

Шаг 3.1Коллекции в деле: groupBy, partition, countBy, keyBy, reduce, when#

Ваш пример с работы — но на данных TaskFlow: построить дерево «воркспейс → доступные роли участников» и посчитать сводку без лишних запросов.

// routes/console.php — снова временная песочница
Artisan::command('collections:play', function () {
    $workspace = Workspace::with('members')->first();

    // группировка по роли — БЕЗ дополнительных запросов, всё уже в памяти
    $byRole = $workspace->members->groupBy(fn ($u) => $u->membership->role->value);
    dump($byRole->map->count());                          // ['owner' => 1, 'member' => 3, ...]  — map->count() = map(fn($c) => $c->count())

    // pluck со вторым аргументом — словарь id => name
    dump($workspace->members->pluck('name', 'id'));

    // partition — разбить на два по условию одним проходом
    [$admins, $rest] = $workspace->members->partition(fn ($u) => $u->membership->isAtLeast(Role::Admin));
    dump($admins->count(), $rest->count());

    // countBy — частотный подсчёт
    dump(Task::all()->countBy(fn ($t) => $t->status->value));

    // keyBy + поиск O(1) вместо O(n) через first()
    $usersById = $workspace->members->keyBy('id');
    dump($usersById->get(1)?->name);                       // без повторного прохода по коллекции

    // reduce — свёртка: суммарная "нагрузка" по исполнителям
    $load = Task::with('assignees')->get()->reduce(function (array $carry, Task $t) {
        foreach ($t->assignees as $u) { $carry[$u->id] = ($carry[$u->id] ?? 0) + 1; }
        return $carry;
    }, []);
    dump($load);

    // when — условный шаг в цепочке без if снаружи
    $q = request()->query('urgent');           // в консоли будет null — это иллюстрация паттерна
    $tasks = Task::query()->when($q, fn ($query) => $query->where('priority', TaskPriority::Urgent->value))->get();
    dump($tasks->count());
});

Все операции — над уже загруженными коллекциями, ни одного дополнительного SQL после первого with('members'). groupBy с замыканием группирует по вычисляемому значению (роль — не колонка БД, а $u->membership->role), reduce строит произвольную структуру, которую ни один built-in метод не построит напрямую.

Зачем: Коллекции — там, где логика уже «в PHP», потому что данные уже загружены: пересчитывать что-то через новый SQL-запрос, когда всё нужное уже в памяти, — трата. Ваш рабочий пример (collect(explode(...))->filter()->values()) — ровно этот же принцип: строку разбили один раз, дальше всё через методы коллекции, а не через array_filter/array_values руками. ->map->count() — «прокси-вызов»: map без замыкания, за которым метод, вызывает этот метод у каждого элемента (higher-order proxy) — короче, чем map(fn ($c) => $c->count()).

// app/Observers/TaskObserver.php
class TaskObserver
{
    public function __construct(private readonly ActivityLogger $activity) {}   // Observer тоже создаётся через контейнер — DI работает

    public function created(Task $task): void
    {
        $this->activity->log($task, 'created');
    }

    public function updating(Task $task): void                          // "updating" — ДО сохранения: isDirty видит несохранённые изменения
    {
        if ($task->isDirty('status')) {

        }
    }

    public function deleted(Task $task): void
    {
        $this->activity->log($task, 'deleted');
    }
}

Шаг 9.2Cache::lock: распределённый мьютекс против гонки при создании#

Распределённый лок — когда двум одновременным запросам нельзя выполнить одно и то же действие параллельно (классика — «дважды нажал сохранить»).

// app/Services/WorkspaceInviter.php — защита от гонки: два одновременных приглашения одного email
public function invite(Workspace $workspace, string $email, Role $role, User $invitedBy): Invitation
{
    return Cache::lock("invite:{$workspace->id}:{$email}", seconds: 10)->block(3, function () use ($workspace, $email, $role, $invitedBy) {
        if ($workspace->invitations()->where('email', $email)->whereNull('accepted_at')->exists()) {
            throw new \RuntimeException('Приглашение уже отправлено и ожидает принятия');
        }
        $invitation = $workspace->invitations()->create([
            'email' => $email, 'role' => $role->value, 'invited_by' => $invitedBy->id, 'token' => Str::random(64),
        ]);
        Mail::to($email)->queue(new WorkspaceInvitationMail($invitation));
        return $invitation;
    });
}

class TaskAssigned implements ShouldBroadcastAfterCommit                 // AfterCommit: не раньше, чем транзакция БД зафиксирована
{
    use Dispatchable, InteractsWithSockets, SerializesModels;

    public function __construct(public readonly Task $task, public readonly User $assignee, public readonly User $assignedBy) {}

}

🔬 Под капотом: Reverb vs Centrifugo: одно и то же место в архитектуре, разная реализация

Reverb — официальный WebSocket-сервер Laravel, говорящий протоколом Pusher; подключается через BROADCAST_CONNECTION=reverb и не требует ничего, кроме самого Laravel-приложения. Centrifugo — отдельный сервис на Go с собственным протоколом (не Pusher-совместимый «из коробки»), для интеграции нужен свой broadcaster-драйвер (пакеты вроде chatecosystem/centrifugo-broadcaster или самописный класс, реализующий Illuminate\Contracts\Broadcasting\Broadcaster) и свой JS-клиент вместо Echo+Pusher. Архитектурно место в проекте — то же самое (событие → broadcastOn → драйвер → клиент), разница — в транспорте и экосистеме. Если увидите Centrifugo на работе — ищите в проекте класс, реализующий контракт Broadcaster, это и есть его «драйвер».

14. Глоссарий #

Service Container — реестр объектов приложения; резолвит зависимости через Reflection и биндинги.
Биндинг (bind/singleton/scoped/instance) — правило «как построить X»: заново, один раз на приложение, один раз на запрос/задачу, готовый объект.
Contextual binding — разная реализация интерфейса для разных потребителей (when/needs/give).
Service Provider — место регистрации биндингов (register) и остальной инициализации (boot).
Facade — статический прокси к объекту из контейнера; тестируется через подмену биндинга.
Eloquent Model — ActiveRecord-обёртка над строкой таблицы: атрибуты, связи, casts, события жизненного цикла.
Query Builder — построитель SQL без привязки к модели; Eloquent\Builder — его расширение с учётом модели.
Отношение (hasMany/belongsTo/belongsToMany/morphMany/morphTo/hasManyThrough) — способ описать связь между таблицами методом модели, возвращающим объект Relation.
Pivot — промежуточная таблица N:M; может быть «немой» или своим Eloquent-классом (->using()).
Eager loading (with) — загрузка связанных записей заранее, отдельными запросами, вместо запроса на каждую в цикле (N+1).
whereHas / withCount — фильтр родителя по наличию связанных записей / подсчёт связанных записей без их загрузки.
Collection — обёртка над массивом с богатым набором методов (map, filter, groupBy...); в основном immutable.
API Resource (JsonResource) — слой представления модели в JSON; whenLoaded/whenCounted показывают поле только если данные подгружены.
Пагинация (paginate/simplePaginate/cursorPaginate) — три способа отдавать список порциями с разной ценой (COUNT, OFFSET, курсор).
Middleware — обёртка вокруг обработки запроса (Decorator); «до» и «после» вызова $next.
Form Request — класс запроса с правилами валидации и проверкой авторизации, резолвится до контроллера.
Route model binding — автоматическая подстановка модели по параметру маршрута вместо ручного find().
Exception Handler (withExceptions) — единая точка превращения исключений в HTTP-ответ.
Guard — механизм определения текущего пользователя (session/token).
Gate — именованная проверка доступа без привязки к конкретной модели.
Policy — класс с методами авторизации для конкретной модели (view/create/update/delete и свои).
Sanctum SPA-режим — аутентификация first-party фронта через сессионный cookie и CSRF, без Bearer-токена.
Event / Listener — факт + независимые обработчики; auto-discovery по типу параметра handle().
Observer — обработчик событий жизненного цикла конкретной модели (creating/created/updating/...).
Job / Queue — единица асинхронной работы; воркер (queue:work) забирает, выполняет, ack/nack по результату.
ShouldQueue / ShouldBeUnique — интерфейсы: «выполнять асинхронно» / «не дублировать, пока предыдущий не завершён».
Mailable — класс, описывающий письмо: тема, содержимое, вложения.
Notification — сообщение, которое можно доставить по нескольким каналам одним классом (mail/database/broadcast/...).
Scheduler (Schedule) — декларативное расписание задач вместо системного crontab с десятком строк.
Cache Manager — единый интерфейс к разным хранилищам кэша (redis/file/array); remember/forget/tags.
Cache::lock — распределённый мьютекс поверх кэша — защита от гонки между параллельными запросами.
RateLimiter / throttle — ограничение частоты запросов, реализовано поверх кэша.
Broadcasting — доставка события во внешний мир (браузер) через WebSocket; PrivateChannel требует авторизации.
Reverb — официальный WebSocket-сервер Laravel, Pusher-совместимый протокол.
Factory — генератор тестовых данных для модели; состояния и has()/for() строят связанные записи.
RefreshDatabase — трейт теста: оборачивает каждый тест в транзакцию, откатывает после.
Fakes (Event/Mail/Notification/Queue::fake) — подмена реального выполнения побочного эффекта проверяемой записью факта.
